# Пользователь получает картинку по тексту

## Description

Эпик ставит платформу и сквозной путь, на котором строится всё остальное: монорепо NestJS, Docker Compose, полную схему `generations` из spine, миграции и локальный запуск одной командой, а поверх них — bot (белый список, `/start`, приём) и worker с конвейером `generation.submit` → `generation.poll` → `generation.deliver` на `advance()`. Telegram-клиент сразу умеет ходить через прокси из конфига. Ошибки пока не классифицируются — эту часть берёт `epic-fault-tolerance`, деплой на VPS — `epic-vps-deploy`.

## Outcome

Пользователь из белого списка пишет боту, запущенному на локальном стеке, сразу видит «принято» и получает изображение ответом на своё сообщение; любой сбой заканчивается текстом, а не молчанием.

## Requirements

- R1 (parent R1): пользователь из белого списка отправляет текст и получает одно изображение ответом на своё сообщение; изображение больше лимита фото Telegram приходит файлом.
- R2 (parent R2): пользователь вне белого списка получает короткий отказ; генерация не запускается, ничего не сохраняется.
- R3 (parent R3): подтверждение «принято» приходит сразу, до готовности изображения; приём новых сообщений не ждёт идущих генераций.
- R4 (parent R4): рестарт bot, worker или postgres во время обработки не теряет принятый запрос — после старта он доходит до изображения или текста ошибки.
- R5 (parent R5): одно сообщение пользователя даёт не больше одной платной генерации, в том числе при повторной доставке обновления Telegram и повторе шага; окно сбоя между приёмом запроса Polza и сохранением её id принято (spine AD-4).
- R6 (parent R7): каждый принятый запрос не позже 30 минут после приёма завершается изображением или понятным текстом: модерация — «запрос отклонён модерацией, переформулируйте», некорректный запрос — «попробуйте изменить текст», остальное — «сервис временно недоступен»; сырой текст ошибки провайдера пользователю не показывается.
- R7 (parent R8): `/start` отвечает приветствием с инструкцией; на не-текстовое сообщение бот подсказывает прислать текстовое описание, генерация не запускается.
- R8 (parent R10): автор по JSON-логам восстанавливает путь любой генерации по `generationId` — шаги, попытки, причину отказа и `trace_id` Polza; 402 и ошибки конфигурации пишутся уровнем `error`.
- R9 (parent R11): весь стек — migrate, postgres, bot, worker — поднимается локально одной командой `docker compose`; упавший процесс поднимается сам.

## Constraints

- Действуют все Constraints инициативы (стек, Polza Media API без идемпотентности, Postgres и pg-boss, один compose-файл, прокси Telegram из env, long polling, модель из `POLZA_MODEL`, раздельное хранение промтов, лимиты Telegram, секреты только в `.env`).

## Done when

- `docker compose up` поднимает migrate, postgres, bot и worker локально; упавший процесс поднимается сам (R9).
- С прокси из конфига и без него bot получает обновления Telegram и отправляет ответы (R1; Constraints инициативы — прокси).
- Пользователь из белого списка получает «принято», затем изображение ответом; изображение больше лимита фото приходит файлом; пользователь вне списка получает отказ и ничего не сохраняется (R1–R3).
- `/start` отвечает приветствием с инструкцией, не-текстовое сообщение — подсказкой (R7).
- Повторная доставка того же обновления не создаёт второй генерации; submit не вызывается, если id Polza уже сохранён (R5).
- Рестарт worker посреди генерации: после старта генерация доходит до изображения или текста ошибки (R4, часть эпика).
- Любая ошибка Polza или Telegram и опрос дольше 10 минут завершают генерацию текстом «сервис временно недоступен»; каждая строка конвейера в JSON-логе содержит `generationId` и очередь (R6, R8, части эпика).

## Boundaries

- Не входит: классификация ошибок Polza и Telegram, повторы с бюджетом, точные тексты по `failure_reason`, общий дедлайн 30 минут, dead letter, корректное завершение по SIGTERM, демонстрация отказов, `trace_id` и уровни ошибок в логах — всё это `epic-fault-tolerance`.
- Не входит: запуск на VPS — `epic-vps-deploy`.
- Touch point: Telegram Bot API — long polling и отправка, через прокси или напрямую; владелец — этот эпик.
- Touch point: xray на хосте автора — только потребляется через адрес входа из env; ставит и настраивает автор, вне compose.
- Touch point: Polza.ai — клиент Media API (создание, опрос, скачивание); владелец — этот эпик.
- Must not change: схема `generations` создаётся целиком по spine, чтобы эпику 2 не понадобились свои миграции; compose-файл один для local и prod.
