- (decision) Парадигма: асинхронный конвейер задач (pipes-and-filters) с явной машиной состояний генерации accepted→submitted→delivering→done|failed; каждый переход — отдельная задача очереди. Binds: bot, worker. Prevents: повтор всей генерации при сбое одного шага.
- (decision) Модульный монолит NestJS: монорепо, два процесса bot и worker, общие libs. Prevents: дрейф контрактов между сервисами, микросервисный оверхед.
- (decision) Postgres — единственный источник истины; очередь pg-boss в той же БД; запись генерации и постановка задачи в одной транзакции. Redis/BullMQ не используем. Prevents: dual-write, потеря принятого запроса.
- (decision) Риск двойного списания принят: окно между submit в Polza и сохранением polza id не закрываем; документируется как осознанный компромисс. Submit не повторяется, если polza id уже сохранён.
- (decision) Результат Polza получаем только опросом GET /v1/media/{id} через отложенные задачи pg-boss; callBackUrl не используем.
- (decision) Telegram: long polling, один инстанс bot; grammY напрямую в своём Nest-провайдере.
- (decision) Наблюдаемость: только структурированные JSON-логи pino с generationId; метрики/Grafana/трейсинг — отложены.
- (decision) Деплой: один VPS вне РФ, Docker Compose: postgres, bot, worker.
